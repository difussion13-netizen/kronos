# Где реально стоят серверы и как это проверить (поправка к выбору региона)

Дата: 2026-09-03. Заменяет рекомендации «us-east-1» в `research-aws-phase0.md` и
`deploy-logger-guide.md` — те исправлены; здесь — методика и источники.

## 1. Факты из первоисточника (docs.polymarket.com, стр. «Geographic Restrictions»)

- **Торговые серверы Polymarket: AWS eu-west-2 = Лондон.** Не Вирджиния — ранее в наших
  заметках было неверное предположение, теперь взято из официальной доки.
- **«Ближайший незапрещённый регион: eu-west-1 (Дублин)»** — так написано у них же.
- Есть официальная колонка «прямая colocation в eu-west-2» для прошедших KYC/KYB-форму
  (для профи; нам пока неактуально).
- Статусы по группам (важно!):
  - «полный блок» (OFAC): Иран, Сирия, Куба, КНДР, Крым/Донецк/Луганск;
  - **«close-only на фронте и API»** — нельзя открывать новые ордера: США, Великобритания,
    Германия, Франция, Италия, Польша, Бельгия, Словакия, Россия, **Беларусь (BY)**,
    Сингапур, Австралия, Новая Зеландия, Бразилия, Канада(4 провинции) и др.
    (Испания/Португалия/Нидерланды — блок только фронтира, API открыт; по сторонним данным.)
  - «close-only только на фронте, **API не ограничен**»: **Ирландия (IE)**, Япония,
    Мальта (спорт). — Отсюда практический вывод: торговый бот через API живёт в
    Дублине (eu-west-1).
    (Нюанс: в доке Нидерланды упомянуты в обеих группах — трактуются как
    «для надежности запрет», поэтому NL не используем.)

## 2. Что это значит для нас

| Контейнер | Правильный регион | Почему |
|---|---|---|
| Логгер (только чтение публичных лент) | eu-west-1, заодно с остальным | чтение ордером не является; но держать всё в одном регионе = нет платы за пересылку данных |
| Будущий GPU для бэктестов | eu-west-1 | S3→GPU внутри региона бесплатно |
| Торговый бот (ордера) | **eu-west-1** | официально «незапрещённый» регион, 1–3 мс до лондонского origin |
| ❌ us-east-1, eu-west-2 (Лондон), eu-central-1 (Франкфурт) | — | US/UK/DE — в close-only; Вирджиния ещё и через Атлантику |

Цена вопроса: eu-west-1 чуть дороже Вирджинии (t3.small ~$16–17/мес вместо $15;
GPU-инстансы +5–10%; точные цифры — калькулятор AWS). Это осмысленная премия за
«боту можно работать с одного места, а торговый контур не упирается в гео».

**Отдельная честная рамка (не юридический совет, а факт):** Беларусь находится в списке
close-only — т.е. по правилам платформы открывать новые позиции нельзя и при заходе
с «правильного» IP вопрос «кого вы видите перед собой» никто не отменял; проверка —
IP и платёжный маршрут. Решение и риски (заморозка позиции, отказ в выплатах, изменения
списка стран — он в 2026 году только расширялся) остаются за владельцем счёта.

## 3. «Как реально узнать, где стоит сервер» — методика

Важно понимать: для биржи существует не «география», а **как ваш IP определён
их гео-базой**. Проверяем три слоя:

**Слой 1 — что о тебе думает Polymarket (главный тест):**
```bash
curl -s https://polymarket.com/api/geoblock
# ожидаем: {"blocked": TRUE, "ip": "34.x", "country": "IE", "region": "L"}   # проверено 2026-09-03
# (!) blocked=true при country=IE — НОРМА: это флаг веб-фронтира («с Ирландии нельзя
# делать ставки руками»), а торговый API для IE по тому же документу открыт.
# Нас в этой проверке интересует поле country — оно должно быть IE и только.
Эндпоинт публичный, отвечает за долю секунды. Если country не IE или blocked=true —
регион «не читается» как надо (такое бывает: базы гео-провайдеров путают AWS-пулы).

**Слой 2 — что о тебе думают гео-базы (для предсказания поведения других сервисов):**
```bash
curl -s https://ipinfo.io/json          # ipinfo — тоже многие сверяются
curl -s 'http://ip-api.com/json/?fields=country,city,org,as,query'
```
и через браузер с сервера/по IP: MaxMind demo (maxmind.com/geoip/geoip2/geolocate —
MaxMind используется Cloudflare, за которым сейчас стоят API Polymarket — проверено:
clob → 104.18.34.205, gamma → 172.64.153.51, оба AS13335 Cloudflare), ipwho.is (флаги
datacenter/proxy — биржи на «облачные» подсети изучают придирчиво).
Кто владеет блоком IP: `whois <IP> | egrep -i 'org|country'` или RIPE Stat
(stat.ripe.net, виджет GeoIP WHOIS). Провайдер «страну» не скроет: блок AMZN-02 в IE
так и пропишется.

**Слой 3 — «промерять путь до origin» — НЕ работает, и вот почему (важная поправка
от 2026-09-03, получена эмпирически с живого дублинского инстанса):**
```bash
for i in 1 2 3 4 5; do curl -o /dev/null -s -w '%{time_connect}\n' https://clob.polymarket.com; done
mtr -rwzbc 30 clob.polymarket.com
```
Результат с сервера в eu-west-1: time_connect 2–3 мс, mtr обрывается на 4–5 хопе
AS13335 (Cloudflare). Что это значит:
- API биржи смотрит в ближайший anycast-узел Cloudflare, а не прямо в origin.
  Значит `time_connect` = расстояние до края CDN, а не до дата-центра Polymarket.
  2–3 мс из Дублина и ~1–10 мс из Вирджинии выглядят одинаково — латентностью
  регион не определяется. Трассировка за Cloudflare не идёт (их магистраль приватна).
- «Лондон (eu-west-2)» как расположение origin принимаем из официальной доки —
  извне это не проверяется. Для нас и не нужно: близкий край CDN = хорошая связь.
- Полезный смысл у теста остаётся один: время соединения с краем Cloudflare и потерь
  нет → до сервера «достучаться» можно. Джиттер на 1–3 хопах (worst 80 мс у AWS-роутеров)
  — это шейпинг ICMP-ответов, его игнорируем, верим только `time_connect`.

**Слой 0 (главный, не серверный, а «удостоверяющий») — где реально стоит ТВОЙ сервер:
ответ даёт сам AWS, а не маркетинг провайдера и не гео-базы:**
```bash
curl -s http://169.254.169.254/latest/dynamic/instance-identity/document
# ждём JSON: "region": "eu-west-1", "availabilityZone": "eu-west-1?", "instanceId": "i-..."
# если curl вернет ошибку (включён IMDSv2):
TOKEN=$(curl -s -X PUT http://169.254.169.254/latest/api/token -H 'X-aws-ec2-metadata-token-ttl-seconds: 300')
curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/dynamic/instance-identity/document
```
Побочные приметы «это AWS, а не что-то ещё» (из того же замера): имя хоста
`ip-172-31-*`, хопы 1–2 из неаллоцированного пространства (242.17.128/19, 240.5/16 —
AWS так размечает внутреннюю пиринговую сеть; RDAP на них вообще не отвечает), хоп 3
151.148.15.225 — блок 151.148/16 зарегистрирован на Amazon (ARIN, «AWS RPKI
Management»). Всё вместе = типичный путь EC2; но регион подтверждает только JSON выше.

## 4. Правильный порядок действий при заказе сервера (дешёвая страховка)

1. Запусти самый маленький инстанс в регионе на 15 минут (~$0.005–0.01).
2. `curl geoblock` → ждём `country: IE` (flag `blocked` при IE=true — норма, он про фронтир).
3. Прогони `time_connect` до clob/gamma — это проверка «сеть живая», НЕ проверка региона.
4. Только после этого переноси конфигурацию/аккаунт бота; если geoblock «видит» не IE —
   не борись: смени AZ/подсеть (перезапусти инстанс — AWS выдаст другой IP из пула) или
   регион (Амстердам у GCP как резервный вариант «API не ограничен»).
5. Раз в месяц перепроверяй geoblock и список restricted-стран (документация Polymarket
   обновляется; в 2026 список только расширился на Бразилию/Словакию/Нидерланды-фронт).
