## 0. Что за направление и где мы

Замысел: маркет-мейкинг на 5m/15m/4h up/down-рынках Polymarket (книги с CLOB WS).
Торговать нельзя до решения по ToS — поэтому фаза MM = **бумажный симулятор на
сырых логах**. Мы на шаге M5 (гейт прохода в модель очереди). Данные пишутся с
03.09, качество потока вышло на проектную только к 17.09 (см. §3).

## 1. Что работает и не требует внимания

- **Логгер** (`logger/kronolog.py`, build `743764b`, systemd `kronolog.service`
  на t3.small-логгере eu-west-1, IP-группа только egress-443):
  - discovery Gamma по слотам с ретраями до конца окна (урок 15m-дня 14.09);
  - **8 WS-соединений** (btc/eth/xrp/sol × fast{5m} / slow{15m,4h}), по 6–8 id;
  - аддитивная дописка новых id (без reconnect-шторма), кап `sub_ids` живым
    набором, **ротационный реснапшот 6 id/цикл** (молчаливые рынки иначе не
    попадают в лог вообще);
  - писатель без блокировок: конверт строкой (без json round-trip), flush по
    байтам, без fsync;
  - вежливый backoff 3–6 с на 1013; лог сервиса — файл `/var/log/kronolog.log`
    (logrotate daily×7), journald ограничен (200M/30M/maxfile 1d, без компрессии
    и sealed).
- **Выгрузка**: PartWriter → `.jsonl.gz` части (ротация 15 мин / 256 МБ) → S3
  `s3://kronolog-moi1234/kronolog/{clob,clob_meta,binance,rtds}/YYYYMMDD/`,
  delete-after-upload. Диск 13%.
- **Аналитика** (`analysis/`): `clobwin.py` (passA regex-id → passB gamma-карта
  → passC книги+чекпоинты; `--days A-B --outdir --map-s3 --minutes --jobs 0`,
  инкремент по `.days`), `clobmm.py` (симулятор сеток k×f, P&L + markout, сводка
  `mm_summary.json`).
- **Изоляция экспериментов**: превью-прогоны делаются клоном канона на отдельный
  ключ (`kronos/prev1516/tokens_map.json{,.days,.ids}`) — канон
  `kronos/win/tokens_map.json` остаётся чистым для финального прогона.

## 3. Что НЕ вышло (честно, включая мои промахи)

1. **Сутки 14.09 безвозвратно битые по 15m** (0 окон серии до 18:47) — логгер
   терял серию из-за отказа одного Gamma-запроса без ретрая + reconnect-шторм.
2. **15.09 (и 16.09 до реснапшота) — потеряно ~2/3 «молчаливых» окон** (947 id
   вместо ~3k/сутки). Причина: биржа не шлёт книги рынку без событий, а старые
   реконнекты бесплатно реснапшотили всё; когда шторм вылечили — бонус ушёл.
   Починено реснапшот-ротацией `743764b` (16.09 17:49); с 17.09 сутки полные
   (проверка: в файле за 20 мин 45+ уникальных id — уже видно 48).
3. **Фризы машины 16.09 16:44–17:22**: journald упёрся в лимит файла, ротация
   встала, блокировка сокета /dev/log заморозила и сервис (log.info), и шеллы.
   37 минут данных потеряно (дыра 16.09, учтена). Лечится только что
   сделанным `append:` + лимитами journald.
4. **Мой баг-деплоi `eda2747`**: `asyncio.TaskGroup` на venv 3.9 → краш-луп на
   40+ минут, обрезанный status.json. Вылечен `1aa835d` (gather). Урок: venv
   машины — 3.9.25, никакой синтаксис/атрибуты 3.10+ без `from __future__`.
5. **1013 slow consumer на одном широком соединении** (38/30 мин) → сплит по
   активам не помог полностью (btc 880/48ч) → сплит по сериям (16.09) — с
   реснапшотом счётчик за 40 мин = 0; следить, пока 1013/сутки не единицы.
6. Мелочи: rtds idle-реконнекты по ночам (watchdog 90 с против разреженных
   chainlink-апдейтов) — оставлено как есть, поток вспомогательный; кэш
   raw.githubusercontent лечится `?nc=<sha>`; `aws` под SSM-сессиями — только
   через профиль инстанса.

## 5. Запасные пути (предрешены, по триггерам)

- **1013 пачками после 17.09** → `resnapshot_ids: 3`; не поможет → `0`
  (только аддитивка, смириться с молчунами) или `lookahead_s: 60`
  (меньше параллельных подписок); не поможет → предположить per-IP лимит
  биржи: разнести 8 соединений по двум ENI/эластичным IP.
- **Окон на 17–20 опять <1000/сутки** → виновник снова discovery: `--map-fill`
  отдельным мягким проходом по ids дня (ретраи gamma, батч 4) и/или
  `--rescan`; данные при этом не теряются — это аналитический шаг.
- **Gamma-429 волнами в логгере** (`grep -c "повтор" /var/log/kronolog.log`) →
  `discover_every_s: 90` в конфиге, одной строкой.
- **Сервис снова «висит»** (network-in в нуле > 10 мин) → `systemctl restart
  kronolog` (части досборются scan_orphans); повтор фриза с чистым логом →
  включить `sd_notify`-watchdog (`WatchdogSec=180`) — заготовка на ветке не
  нужна, это 3 строки unit-файла.
- **М5 непройден, но markout ∈ (−1.5¢; −0.5¢)** → не хоронить: одна итерация
  «очередь+ширина» на тех же сутках (это уже модель очереди как диагностика,
  не сделка); повторный непроход — финальный протокол.
- **Дыра ≥3 ч в сутках 17–20** (сбой логгера) → сутки не выбрасываем,
  считаем гейт по полным (правило «6 свежих суток» допускает 6 из 7).

  .bak*) → restart → `tail /var/log/kronolog.log` (8 subscribed) → через 30
  мин счётчик 1013 и уникальные id в свежей части.
