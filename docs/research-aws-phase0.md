## 0. Логика разделения

Система распадается на три «потока» с очень разными требованиями, их наём оплачивается раздельно:

1. **Накопитель (24/7, CPU, дешёвый, критичен к надёжности)** — стрим-логгер
   Binance trades/depth/klines + Polymarket RTDS (Chainlink) + CLOB-стаканы, парquet-чанки в S3.
   Это запускается **первым и не выключается никогда**: Chainlink/RTDS-историю иначе не купить.
2. **Вычисления (рваный режим, GPU, оплачивается по часам)** — бэкфилл/конвертация,
   walk-forward бэктесты (фаза 2–4), файнтюн (фаза 5). Spot-инстансы, поднял-прогнал-сдал.
3. **Live (24/7, GPU, появится в фазах 7–8)** — инференс Kronos + стратегия + исполнение.
   В фазе 0 его не покупаем; но сразу проектируем накопитель так, чтобы live-бокс мог
   читать тот же S3-датасет.

## 1. Оценки данных (чтобы не перекупить диски)

| Поток | Сырьё/сутки | Parquet/сутки | Комментарий |
|---|---|---|---|
| Binance klines 1m/5m (live-дописывание) | ~1–2 MB | <1 MB | история берётся из бэкфилла, не из WS |
| Binance `btcusdt@aggTrade` | 0.3–1.5 GB | 100–400 MB | aggTrade в ~10 раз компактнее raw trades, для наших фич достаточно |
| Binance `@depth5@100ms` (L2 top-5) | 0.4–1 GB | 100–250 MB | полный `@depth` (все уровни) — 3–30×; включать только в фазе 6 и с фильтром |
| Polymarket RTDS (Chainlink BTC/USD) | 0.1–0.4 GB | 30–100 MB | единственный источник «истинной» цены резолва |
| Polymarket CLOB books+trades (только активные 5-min рынки) | 0.2–0.8 GB | 80–300 MB | ~2 токена на окно, 288 окон/сутки |
| **Итого** | ~1–4 GB/сутки | **~0.4–1 GB/сутки** | **≈ 12–30 GB/месяц** → на год ≈ 0.2–0.4 TB |

Бэкфилл (одноразово): Binance 1m/5m/1h/1d с 2020 — **бесплатно** с публичного зеркала
`data.binance.vision` (csv-архивы по месяцам, ~2–6 GB на все таймфреймы 5 лет, без лимитов API).
Gamma API отдаёт историю рынков `btc-up-or-down-5m` (closed=true) с исходами — ~миллионы
строок, сотни MB; исторические трейды рынка — `data-api.polymarket.com/trades` (страницами).
Чего **нельзя** скачать задним числом: тики Chainlink-стрима, L2-снимки и стаканы CLOB —
только собственная запись с сегодняшнего дня.

## 2. Конфигурация «Накопление истории» (месяц 0–2)

| Ресурс | Спецификация | Назначение | $/мес |
|---|---|---|---|
| EC2 `t3.large` (2c/8GB) или `c6i.large` | 24/7 on-demand, 30–50 GB gp3 | стрим-логгер (все 5 потоков), буфер + партиции, uploader | ~$61–62 (+EBS ~$4) |
| S3 `kronos-data` (us-east-1) | Standard → IA lifecycle с 90 дн | витрина данных, immutable чанки | ~$1–3 при 50 GB |
| S3 PUT/GET, трафик | входящий бесплатен | выгрузка на GPU-боксы в том же регионе бесплатна | ~0–2 |
| Public IPv4 (на инстанс, $0.005/ч) | — | или без него: выход через NAT gateway… не нужно, у инстанса есть public IP при запуске | ~$4 |
| CloudWatch логи (сэмплированные) + аларты | метрики CPU/диск/«поток молчит N сек» + SNS email | дежурство | ~5–10 |
| **Итого** | | | **≈ $75–85/мес** |

Почему t3.large, а не t3.medium: пиковые секунды на BTC (новости, ликвидация-каскады)
дают десятки тысяч msg/s; парсинг JSON + сжатие zstd + fsync хотят голову CPU.
t3 — burstable: следить за CPU credit balance, либо сразу c6i/m6i (неburstable). Диск —
EBS gp3 50 GB только под буфер (сутки хранения), всё дальнее уже в S3; потеря инстанса
= потеря ≤24 ч, ресинк по таймстемпам идемпотентен.

Отдельная экономия: тот же логгер без изменений потом становится «ухом» live-системы,
поэтому не экономить на регионе/сете — см. раздел 4.

Бэкфилл `data.binance.vision` + конвертация в parquet разово: spot `c6i.4xlarge`
(16 vCPU, без GPU) 2–4 часа → **$2–4 одноразово**.

## 3. Конфигурация «Полноценная работа» (фазы 2–8, растёт волнами)

### 3.1. Вычислительный контур (бэктесты, калибровка, файнтюн) — spot, по требованию

| Задача | Инстанс | Часы | $ |
|---|---|---|---|
| Walk-forward PoC (Фаза 2): Kronos-small, N=128×предсказаний на ~90 дней ×288 окон (~26k инференсов) | `g5.xlarge` spot (A10G 24GB) ~$0.55–0.70/ч | 10–30 ч/нед | $60–150/мес |
| Микроструктурные фичи из 3 мес записей (Фаза 6 пред-подготовка) | тот же или `m6i.4xlarge` spot | 10–40 ч | $20–60 |
| Файнтюн tokenizer+predictor на BTC 5m (Фаза 5) | `g5.xlarge`/`g5.2xlarge` spot, чекпойнты на EBS gp3 200 GB | 1–2 дня | $30–80 разово |
| Хранение датасета на время прогонов | EBS gp3 (снимок в S3 на паузах) | — | $8–16/мес |

Для нашего случая **не нужны** многосекундные «обучалки»: весь Kronos-small/base
(25–102M параметров) и датасет BTC 5m (~0.4 млн свечей на 4 года) — это A10G/L4
на несколько часов. g6-family (L4) аналогичен по цене/возможностям, если g5 в spot-дефиците.

### 3.2. Live-контур (Фаза 7 paper → Фаза 8 пилот) — один 24/7 GPU-бокс

| Ресурс | Спецификация | Назначение | $/мес |
|---|---|---|---|
| EC2 `g4dn.xlarge` on-demand (T4 16GB, 4c/16GB) | 24/7, EBS gp3 100 GB | inference-сервис (small/base, батч 128 путей ≈ 1–3 с, бюджет решения минуты — ОК) + стратегия + исполнение | **$384** (+EBS $8) |
| Резерв по мощности | переход на `g5.xlarge` ($734) или g4dn 1-yr Reserved (~$250) | если сэмпл-бюджет N≥512 или добавится вторая модель | +$0–350 |
| Секундомер надёжности | CloudWatch + алерт «нет сделки/нет тика/ошибка CLOB 4xx» → SNS/Telegram; systemd Restart; health-эндпоинт | kill switch вручную по SSM | ~$10 |
| Секреты | SSM Parameter Store SecureString (Binance read-only API key; приватный ключ — только hot-кошелёк с лимитом депозита) | без ключей в AMI/дисках | ~0–1 |
| **Итого live** | | | **≈ $410–450/мес** (reserved-вариант ≈ $290) |

Замечания по архитектуре live:
- Paper-trading (Фаза 7) гоняется **на этом же боксе и в этом же коде**, только
  исполнитель — «симулятор по стакану». Так live-пилот = флиг дактаила, а не переписывание.
- Если к фазе 8 захотим sniping в последние секунды окна — добавляется второй,
  «токийский» инстанс (`t3.small`, ~$15/мес) только для низколагентного чтения Binance,
  и решение синхронизируется через Redis/Postgres на основном боксе. На maker-стратегии
  ~150–200 мс из us-east-1 до Binance — не ограничивающий фактор (5-мин окно).
- Polymarket CLOB/Gamma и RTDS живут в US East → инференс-бокс держим в us-east-1
  (~15 мс до биржи предсказаний; SSH из Беларуси через SSM комфортен в любом регионе).

## 5. Чеклист заказа ресурсов (Фаза 0, ~полдня руками)

1. **Отдельный AWS-аккаунт** (не тот же, где прочее) → us-east-1; IAM: только роль
   для инстансов; доступ к консоли через SSO/MFA. Billing alerts $50/$150/$400.
2. S3 `kronos-data-<имя>`: versioning off, SSE-KMS, lifecycle: Standard→IA 90d→Glacier 1y;
   политика «write-through инстанс-роли», аксесс-кеев на диске нет.
3. EC2 `t3.large` (Ubuntu 22.04/24.04 ARM не брать — x86 для совместимости с GPU-окружением),
   роль EC2→S3; Security Group: **входящих портов нет вообще** (вход только SSM Session Manager),
   исходящие 443. Docker/compose или venv+systemd — на вкус, состояние минимальное.
4. Завести запись RTDS и CLOB **в первый же день** (история, которой нет на рынке, — наше узкое место).
5. Бэкфилл: `data.binance.vision` → S3 (сырьё) → spot `c6i.4xlarge` → parquet → S3 `kronos-data/btc/klines/`.
6. Метрики и аларты: `stream_age_seconds` (по каждому из 5 потоков), disk free, credit balance,
   uploader-lag → CloudWatch → SNS email (позже Telegram).
7. GPU-бокс **не покупаем** до выхода на Gate #1: до него всё считается на spot вручную
   (`aws ec2 request-spot-instances` или скрипт «поднял-прогнал-убил» — будет в фазе 2 кодом).
8. Секреты бирж/hot-кошелёк заводить только к фазе 7; сейчас только read-only Binance key (для REST-бэкфилла, если vision-зеркала не хватит) — его и в SSM.

## 6. Что здесь намеренно НЕ нужно

- Kubernetes/ECS/EKS — перебор: три systemd-юнита. ECS Fargate только если захотим
  гонять батчи на spot fleet автоматически (потом).
- Kafka/Kinesis — буфер на локальном диске + парquet-чанки достаточно (rampy-стримы,
  ретранcляция никому не нужна).
- RDS/DynamoDB — журнал сделок/решений = SQLite на EBS (ночной снапшот в S3); при росте — Postgres на том же боксе.
- Отдельный «холодный хранилищный» сервис — S3 lifecycle закрывает.
- HFT-лизинг/приватные связи: горизонт 5 мин это не требует.

## 6a. Приложение: Binance — что можно докачать в любой момент, а что нет

(проверено по README `binance/binance-public-data` + `data.binance.vision`, 2026-09)

Скачиваются постфактум бесплатно, логгер для истории НЕ нужен:
- **Спот klines: все интервалы, включая `1s`** (`1s,1m,…,1d,1w,1mo`) — месячные/дневные
  zip, для BTCUSDT — с листинга (2017; ранние 1s-файлы проверить фактическим списком
  `data/spot/monthly/klines/BTCUSDT/1s/` при бэкфилле); дневные файлы появляются на
  следующий день, месячные — в первый понедельник месяца. Для Kronos этого достаточно
  со с запасом (модель ест 1m/5m-свечи).
- **Спот raw trades** (полная лента: цена, кол-во, мкс-таймстамп с 01.01.2025, `isBuyerMaker`)
  и **aggTrades** → из них в любой момент реконструируются 1-сек бары, flow-imbalance,
  taker-buy volume, VWAP-фичи для второй модели.
- **Фьючерсы UM**: klines, trades, aggTrades; плюс в архивах исторические `metrics`
  (open interest, long/short), `bookTicker` (лучшие bid/ask), `bookDepth` (агрегированные
  статистики глубины 1s/1m), `premiumIndexKlines` (funding), `liquidationSnapshot`.
- Целостность: `.CHECKSUM` (sha256) на каждый zip; Binance иногда выкладывает фиксы
  архивов → бэкфилл делаем идемпотентно по «месяц-файл-ключ», при повторе перезаписываем.

НЕ скачивается постфактум (только своя запись или платный вендор типа Tardis.dev/Kaiko):
- **полный L2-стакан спота** (снимки+дельты по уровням);
- спотовый best bid/ask (bookTicker есть только у фьючерсов).

Решение по фазе 0:
- Логгер Binance НЕ является блокером: фазы 2–5 стартуют с бэкфилла в один вечер.
- `depth5@100ms` спота включаем в логгер «заодно» (наценка ~$0/мес к уже запущенному
  логгеру, +0.1–0.3 GB/сутки) — это бесплатная страховка для фазы 6 вместо покупки
  истории у вендора. Отложить — можно, ничего критичного не потеряем кроме глубины
  прошлых месяцев.
- На live-этапе (фаза 7) Binance-стримы будут подключены к live-боксу как рантайм-вход —
  это не «архивный» логгер, а штатное потребление биржи.

## 7. Риски и оговорки

- **Юрисдикция/compliance**: доступность Binance и Polymarket для резидента РБ и условия
  их ToS (включая автоматизированную торговлю и «restricted jurisdictions») проверить
  самостоятельно; AWS к самим рынкам отношения не имеет, но депозит/вывод — узкое место.
  Это не юридическая консультация.
- Цены spot волатильны (g5.xlarge в us-east-1 качался $0.25–0.95/ч за последние месяцы) —
  для budget-спокойствия можно `--capacity-optimizer` пул или просто g6 on-demand на время прогонов.
- t3 burstable: при длительном >40% CPU кредиты кончатся и стрим начнёт отставать —
  алерт на `CPUCreditBalance` обязателен; переход на c6i.large решает вопрос за +$0.
- Egress из S3 наружу (не в тот же регион) — $0.09/GB: датасет не «катить» к себе на ноут
  целиком, только срезы.
- Приватный ключ Polymarket-кошелька на облачном инстансе = компрометируемый актив:
  лимит депозита, отдельный кошелёк, вывод по расписанию, никогда в AMI/снипшотах.
