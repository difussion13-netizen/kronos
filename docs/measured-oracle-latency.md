# Замеренные параметры оракула Polymarket (первый прогон анализатора)

Дата: 2026-09-08 (данные 2026-09-03…09-07, ~3.9 суток, Дублин eu-west-1).
Инструмент: `analysis/kreader.py lag --days ... --files 0 --thresh 5` (методика в
`analysis/README.md`). Символ btc/usd. Ряды: Binance aggTrade 6 362 932 точек
(54% с event-ts, остальное depth5 по времени приёма), Chainlink 31 469 точек —
т.е. ~1 обновление оракула на 10.8 с.

| метрика | медиана | p90 | что значит |
|---|---|---|---|
| цена CL vs mid Binance в метку времени | 0.81 б.п. | 1.85 б.п. | оракул точен, метки честные |
| цена CL vs mid Binance в момент приёма | 1.30 б.п. | 4.02 б.п. | шум, с которым резолвится рынок |
| «возраст» цены внутри сообщения CL | 30.7 с | 54.1 с | период обновления оракула |
| доезд движения >5 б.п. до CL | 17.6 с | 52.4 с (n=38) | реакция оракула на импульс |

Выводы для проекта (этапы B–D):
1. Ограничитель — НЕ оракул: при окнах 5м/15м отставание 31–54 с несущественно;
   модель видит к закрытию окна всё, что увидит резолв.
2. Пол шума: движения <~3–5 б.п. (≈ $2–4 на BTC за 15 мин на спокойном рынке) для
   нас нерезолвимы — прогнозы с «краем» меньше этого = монетка; порог уверенности
   модели надо калибровать об эту величину.
3. Плотности данных хватает: ~6.3 млн ценных точек Binance + 31.5 тыс. CL-обновлений
   на 4 суток → недельный датасет годится для smoke-теста Kronos, полный вывод —
   после плановых ~150 дней.
4. Методика воспроизводима: повторить замер = та же команда; --sym eth/usd для
   симметрии. После смены конъюнктуры (волатильность ×3) — перемерить, пороги поплывут.
