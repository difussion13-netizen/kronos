# Горизонт накопления данных, мульти-рыночность и выбор таймфрейма для MM

Дата: 2026-09-03. Связано: `research-aws-phase0.md`, `research-mm-vs-directional.md`.

## 0. Ответы в одну строку

1. **Критический путь накопления — 4–6 недель, и почти всё остальное доступно уже сегодня.**
   Для модели и разметки записывать ничего не надо (бэкфилл бесплатный); ждать нужно
   только микро-структурным данным (книги CLOB, точные тики Chainlink) и markout-статистике paper-периода.
2. **Зависимость «объём → качество» существует, но ломается рано:** всё, что связано с
   предобученным Kronos + калибровкой, выходит на плато за 3–4 недели записи / 3–4 года
   истории свечей. Дальше качество определяют свежесть режима и число собственных fills,
   а не глубина архива.
3. **Накапливать широко, исследовать узко:** логгер — на все серии и активы (копеечная
   предельная стоимость, ×10 выборка для механики MM, опцион на масштабирование);
   модель/PoC — строго BTC, сначала 5m (+1m для mid-window).
4. **MM-пилот: 15-min серия — лучший риск/сложность; 4h — второй, «тихий» контур;
   5m — заходить после отладки стека** (по предрегистрированной метрике net-spread, §4).

## 1. Что и когда становится пригодным (разбивка по датасетам)

| Датасет | Как добывается | Когда пригоден к использованию | Плато качества |
|---|---|---|---|
| Binance klines 1s…1d, trades/aggTrades, фьюч-метрики (O/Funding/OI) | бэкфилл `data.binance.vision` | **день 0–1** (вечер на закачку ~10–60 GB + конвертацию) | неограниченно полезно до ~3–4 лет; старше — вред от устаревших режимов |
| Метка резолва (Chainlink TWAP) для 2020–2026 | аппроксимация из Binance 1s (TWAP30 из 1-sek баров) + исходы рынков из Gamma | **день 0–2** (приближённо), own-запись для точной | базис Binance↔Chainlink: 2–4 недели записи |
| Цепные RTDS-тики (истинная цена резолва) | только своя запись | **2 недели** для базис-регрессии; 4–6 нед для уверенных хвостов | +месяц для редких всплесков; дальше — перманентный фоновый сбор |
| Книги CLOB 5m/15m/4h серий (спреды, глубина, размер очереди, потоки) | только своя запись (исторические **трейды** частично подкачиваются: `data-api /trades` страницами — проверить лимит offset) | **2 недели** — «нулевая гипотеза MM» и расчёт net-spread по сериям; **4–6 недель** — надёжные оценки по режимам | плато ~8–12 недель; редкие режимы (новости, каскейды) — просто продолжать писать |
| Calibrated P(Up) поверх zero-shot (изотоника/Platt на окнах) | из всего выше | **3–4 недели** окон (BTC 5m: ~8.6k окон/мес; ×серии ×активы >60k) | SE калибровки ∝ 1/√n: 8k→20k событий — ×1.6 точнее; дальше — только стратификация по режимам |
| Fine-tuned Kronos на BTC 5m | история + GPU, запись не нужна | **1–2 недели** с нуля (скачал — обучил) | 300–500k свечей (≈3–4 года 5m) — далее отдача ≈ 0, важнее свежий период |
| Markout собственных fills (главная MM-метрика) | paper-прогон на реальном CLOB | **2–4 недели** paper (1–2k fills на режим) | перманентный мониторинг, не «накопление» |

Вывод по срокам: **сегодня** можно запустить всё исследование модели (фаза 2–4 исходного
плана) на бесплатном бэкфилле; **через 2 недели** — осмысленный расчёт MM-экономики по
записям; **через 4–6 недель** — решение о live с закрытыми гейтами. «Месяцев копить
историю» не требуется ни для одного этапа — это миф, порождённый незнанием, что
Binance-архивы и лента Polymarket открыты, а модель предобучена на 12 млрд свечей.

## 2. Объём → качество: где кривые плато

- **Fine-tune генератора (Kronos).** Модель предобучена (12 млрд K-баров, крипта
  апсэмплирована); файнтюн — адаптация, не обучение с нуля. Ожидаемо: +первые 50–100k
  5m-свечей дают основной сдвиг (домен BTC: тонкие книги, ночные режимы, каскейды
  ликвидаций), 300–500k — плато, 1M+ — ≈0 прицельного выигрыша, а 5–8-летние данные
  скорее вредят (микроструктура 2018 ≠ 2026; лучше экспоненциальное затухание весов
  по давности, чем отказ).
- **Калибровка вероятностей.** Точность reliability-кривой ∝ 1/√n событий:
  ~10k окон — ±1¢ к калибровочной ошибке, ~40k — ±0.5¢. 4 недели записи достаточно,
  чтобы стратифицировать по 3–4 режимам (тишина/норма/шторм) и не переобучаться на шуме.
- **MM-механика (net-spread, fill-вероятности, queue-модель).** Требует событий «fill
  в конкретном месте книги»: ~1–2k филов на бакет — при нашей интенсивности рынков
  (7 активов × 288+96+6 окон/сутки) это **2–4 недели**, а не «полгода».
- Что растёт без плато и потому пишется вечно: редкие хвостовые события (TWAP-края,
  новостные всплески) и декалибровка на сменах режима. Отсюда правило: **логгер
  не выключать никогда; исследования — запускать, не дожидаясь**.

## 3. Мульти-актив и мульти-таймфрейм: накапливать — да; исследовать — с фокусом

**Записывать — всё:** `btc/eth/sol/xrp/hype/bnb/doge/zcash` × `5m/15m/4h` (+hourly,
если ещё жива; проверить по Gamma lineup) + RTDS по всем активам. Предельные издержки
≈ 0 (0.1–0.3 GB/сутки на каждый актив на логгере, который уже запущен ради базового
случая). Выгоды:
1. Механика MM (спред-режимы, очереди, паттерны toxic-flow) актив-агностична →
   ~×10–20 выборка для одних и тех же оценок, которые иначе требуют месяцев;
2. Готовые кросс-активные фичи (Binance-лид BTC → lag-структура для ETH/SOL);
3. Опцион на масштабирование capacity: live-лимиты одной серии малы, трёх серий — уже
   осмысленный P&L.

**Модель — узко и по иерархии:** ядро = BTC 5m (+1m-ветка для mid-window/15m-прогноза
агрегированием). ETH/SOL — вторым эшелоном: тот же код, свои тонкие калибровки (у
альтов иные спреды/толщины, фичи переносимы не всё). 15-min/4h-серии: не отдельная
«большая» модель — сдвиг интервала входа (агрегат из 1m/5m) и своя калибровка;
сама архитектура и файнтюн-пайплайн не меняются.

**Правило пула данных:** механические оценки (spread, queue, toxicity-базовые ставки) —
пулить по всем активам с иерархическим shrunk-взвешиванием на BTC; вероятностные —
только свой актив+серия, иначе смешаем разную физику.

## 4. Какой таймфрейм котировать MM

Матрица (оценки — из §1-источников 2026; «нетто» — предрегистрируемая метрика §4.1):

| Фактор | 5-min | 15-min | 4-hour |
|---|---|---|---|
| Окно/день/актив | 288 | 96 | 6 |
| Ретейл-флов (двигатель ребейта) | макс ($60M/сутки на BTC-5m) | высокий | низкий на окно, но длинные удержания |
| Спреды | сжаты к 1¢ (проф. конкуренция) | 1–2¢ | шире (2–5¢+) |
| Доход/окно | минимальный ×288 | средний ×96 | крупный ×6 |
| Endgame-токсичность (снайперы у TWAP-края) | **максимальная**: последние 30–60 с — латентная гонка | средняя (TWAP 60с при окне 900с — мягче) | низкая: исход определяется дрейфом часов, а не тиками |
| Требования к латентности снятия котировок | <150–250 мс обязательны | 300–800 мс терпимо | секунды достаточны |
| Скорость дрейфа miд (ошибки квотинга) | высокая — γ-взрыв к концу | умеренная | медленная, управляемая skew |
| Прелесть для reward-скоринга (time-in-book × близость к mid) | время жизни ордера ≤5 мин — кредит копится плохо | хорошо | **лучше всего**: ордера живут часами, близость держится |
| Польза модели- governor (σ-прогноз, burst-детект) | максимальная | высокая | средняя (доминирует макрориск, не микроструктура) |
| Ops-нагрузка (циклы split/merge, ребаланс, мониторинг) | экстремальная | средняя | низкая |

**Рекомендация (порядок, а не «выбор одного»):**
1. **Пилот: 15-min BTC (+ETH как второй).** Медленные часы, спред ещё не утилизирован
   конкурентами до дна, endgame поддается our-stack-латентности, модель-фильтр уже
   полезен. Это «полигон», на котором отлаживается 100% того же кода, что нужен для 5m.
2. **5-min: заходить после того, как на 15m две недели net-spread ≥ 0.** Идти «в лоб»
   на самый окисленный рынок — самый частый способ убить проект до статистики.
   К тому моменту (неделя ~5–6 с учётом 4–6 нед записи+paper) будет и измеренный
   «налог на снайперов», и честный ответ, нужен ли speed-up (colo-токийский узел и т.п.).
3. **4h: параллельно, как «ферма» с минимальным ops** — широкий спокойный квот,
   доход от time-in-book + близости; диверсифицирует P&L и покрывает простой 5m-этапа.
   Капитал-требование единственное — позиции на сутки.

### 4.1. Предрегистрированная метрика выбора (чтобы не гадать)
По 4 неделям записей, на каждую серию: `E$ = (½spread + rebate_share + rewards_est) −
|markout_fill|`, на 1$ заявленной котировки в сутки; решение о live-серии — при
E$ > 0 c 95% CI на дневной выборке из ≥15 дней. Это же — арбитр спора «5m vs 15m»,
который по априори не решить (в §4 я дал priors, не догму).

## 5. Что конкретно делает «накопление» ненужным блокером (напоминание)
Клайны Binance (0), фьюч-метрики (0), лента трейдов Polymarket через data-api (0,
проверить лимиты), исходы/разметка окон из Gamma (0), «псевдо-TWAP» из Binance-1s (0).
Запись нужна ровно на две вещи без замен: **книги CLOB** и **тики RTDS**. Обе — пассивны
и дёшевы; обе покрываются 2–4 неделями для первого решения.
